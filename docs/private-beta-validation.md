# Private-beta usability validation

Use this script with 10–20 invited traders who have not been shown the product.
Do not guide them except to resolve a technical launch problem. Record consent
before collecting the local metrics file or interview answers.

1. Ask the participant to open the worked example, prepare the suggested data,
   and complete the four-year study.
2. Ask what the result does and does not establish. They should distinguish a
   historical result from an unseen-period result and a future forecast.
3. Ask them to identify the worst-case drawdown, the execution-cost assumption,
   and the recommended next action from the result view.
4. Ask them to fork the strategy and make one stated rule more conservative.
   Observe whether they can explain the changed rule before running it.
5. Ask which strategy capability is missing, only after the core journey is
   complete. Categorise this separately from navigation, data, or terminology
   confusion.

Success is a completed first multi-year study without assistance and correct
answers to the interpretation questions. Review aggregate local metrics for
completion, duration, and failures; retain interview notes separately from
strategy files. Prioritise fixes that remove confusion in the core path before
adding requested strategy features.
